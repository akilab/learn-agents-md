会議運営Skillを作ってみよう

自分の会議で手伝ってほしいことを決め、小さく作って試します。

仕組みと配置先を知ったので、AIと相談しながら自分のSkillを一つ作ってみましょう。完成した手順を写すのではなく、用途を決めるところから始めます。

このページの到達点会議運営の一つの作業をSkillにし、認識と結果を確認して改善できます。

会議で手伝ってほしいことを、一つ選ぶ

題材は「会議運営を助けるSkill」です。会議の進め方はチームごとに違うため、決まった運用を再現する課題ではありません。自分の会議で繰り返し頼みたいことを選びます。

会議前の確認事項を整理する、会議メモから決定事項をまとめる、次回の議題候補を整理する、といったことが候補です。最初は一つだけ選び、チャットに結果を返す小さなSkillにします。

テストには架空の短いメモを使えます。実際の会議を始める必要はありません。

何を渡し、何を返してほしいかを決める

Skillの内容をAIと相談します。次の依頼文の「利用ツール」を自分のツール名に書き換えて、今開いているプロジェクトのチャットへ送ります。

Skillの内容を相談する依頼
会議運営を助けるmeeting-helperというSkillを作りたいです。
利用ツール：ここをCodexまたはClaude Codeに書き換えてください。

まず、次の4点を私に確認してください。
1. 会議で手伝ってほしい作業を一つ
2. そのSkillを使うタイミング
3. 渡すメモや、参照する資料の有無
4. 期待する出力の項目や形式

回答をもとに、name・descriptionとMarkdownの本文だけで、
小さなSKILL.mdの案を示してください。
共通の内容でCodexとClaude Codeの両方に配置できる形にしてください。
配置先は、利用ツールに合わせてプロジェクト内の場所を示してください。
まだファイルは作らず、提案してください。

AIから質問されたら、一つずつ回答します。資料がなければ「資料は使わず、チャットに貼るメモを使う」と伝えれば大丈夫です。

ここでは、「会議開始」「会議終了」という合図や、特定の議事録ファイルを必須にしません。自分が使うタイミングと、読み取る情報を決めます。

案を確認して、SKILL.mdを作る

提案された内容を読み、次の点を確認します。

  • 名前はmeeting-helperになっているか。
  • 説明から、どんな作業に使うか分かるか。
  • 本文が、自分の選んだ一つの作業に絞られているか。
  • 入力する情報と、返してほしい結果が明確か。
  • 使うツールに合った配置先が示されているか。

合っていれば、ファイルの作成を依頼します。

確認した案を保存する依頼
確認した案でmeeting-helperのSKILL.mdを作成してください。
このプロジェクト内の、私が利用するツール用の場所へ保存してください。
保存したファイルのパスを示してください。
既存の同名Skillがあれば、上書きする前に内容を確認してください。

保存先は、Codexなら.agents/skills/meeting-helper/SKILL.md、Claude Codeなら.claude/skills/meeting-helper/SKILL.mdです。14の配置表と照らし合わせ、実際にファイルがあることも確認します。

アプリでSkillを見つける

保存したプロジェクトを開いた状態で、アプリのSkill一覧や入力候補にmeeting-helperが出るかを確認します。表示場所はアプリのバージョンで異なることがあります。

Codex

  1. アプリのサイドバーにある「Skills」を開き、meeting-helperを探します。
  2. 名前と説明が、作成した内容になっているか確認します。
  3. プロジェクトのチャットへ戻り、「meeting-helperのSkillを使って」と名前を明記し、次の節の依頼を送ります。

サイドバーの項目や選択画面はバージョンで異なる場合があります。CLIやIDE拡張では/skillsや$meeting-helperでも指定できます。

Claude Code

チャット入力欄に/を入力し、meeting-helperを候補から探します。/meeting-helperで呼び出せます。

候補に表示される名前と、SKILL.mdに書いた名前を照らし合わせます。

見つからない場合は、配置先、SKILL.mdの綴り、先頭の名前と説明、ファイルが保存されているかを確認します。新しい会話で確認し、それでも出なければアプリを再起動します。単にAIへファイルを読ませたことと、Skillとして認識されたことは区別します。

短いメモで試し、結果を確認する

Skillを指定したうえで、次の依頼を送ります。Claude Codeでは/meeting-helperの後ろに依頼文を続けることもできます。

作成したSkillを試す依頼
meeting-helperのSkillを使って、私が渡す会議情報を整理してください。
今回は動作確認なので、回答をチャットに表示し、ファイルは変更しないでください。
不足している情報があれば質問してください。

続けて、自分が選んだ作業に合う短いメモを渡します。AIから不足する情報を聞かれたら回答します。

できたことを確認する

  • 自分が決めた作業に沿った結果が出た。
  • 指定した項目や形式で整理された。
  • メモにない情報を、決定事項として作っていない。
  • 同じSkillで別の短いメモも整理できた。

Skillの使用表示や読み取りの記録が見られる場合は、作ったSKILL.mdが使われたかも確認します。出力が似ているだけで、Skillが使われたと断定しないようにします。

一か所変えて、もう一度試す

期待と違う結果なら、どの点を変えたいかをAIへ伝えます。「未決定の項目を別にする」のように、一か所だけ改善します。

修正されたSKILL.mdを保存し、アプリのSkill一覧と新しい会話で読み込まれた内容を確認してから、同じメモでもう一度試します。両ツールへ配置した場合は、本文を揃えてそれぞれで試します。

開始・終了の合図や、時間通知へ広げたくなったら

基本の作業ができたら、開始時と終了時に行う手順を分けたり、必要な資料を読む条件を加えたりできます。使う合図は本文と説明へ明記し、最初はSkill名を指定して確認します。

時間になったら通知するには、予約・リマインダーなどの実行機能も必要です。SKILL.mdへ「30分前に知らせる」と書くだけでは、予約されたことにはなりません。この実習では時間通知は作りません。

ここで覚えておくこと

用途・入力・期待する結果を決め、小さく作り、実際に試して改善します。
